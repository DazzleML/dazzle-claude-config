## Re-aimed mutants

The consolidation into `NOT_AN_OBJECT` / `not_valid_json()` deleted the code M6 and M7 targeted -- `unreadable_reason` no longer re-derives the wording by substring sniffing, because `plan_config` now stores the sentence that gets printed. The risk moved with the code, so the mutants moved too:

- **M6** now makes `plan_config` write its own wording instead of the shared one.
- **M7** now reverts `load()` to the parser's class name.
- **M14** (new) adds a third hand-written copy of the not-an-object sentence.

All three die. That is the point of the consolidation stated as a test.

## Two tests that were wrong about their own subject

Worth more than the kill count, and neither was found by the sweep itself -- both surfaced while auditing it.

**One passed because of its own name.** `test_all_still_says_unmodified_when_the_copy_really_was` asserted `"unmodified" in out`. pytest names its temp directory after the test function, that path is printed in the backup line, and the assertion was matching the *directory name*. It passed with the message deleted entirely. A grep for the pattern found a second instance -- `test_an_unmodified_retired_file_is_removed_by_default` -- which had been passing that way since it was written. Both now assert the full phrase.

**One failed because of its own parsing.** The column-alignment test took `line.split()[1]` as the filename, which holds only while every verdict label is a single word. Adding a live-only file introduced `"live only"`, two words, so it measured the column of the word "only" and reported a misalignment that did not exist. The output had been correct throughout.

## Caveats

- **A kill proves the suite noticed *this* change, not that it tests the right thing.**
- **A clean sweep is evidence about the mutations tried, not proof of suite completeness.**
- Rounds 2 and 3 re-ran a largely unchanged population, so they confirm the new tests kill what they were written for -- the close-the-loop check, not an independent second opinion.
