## Survivor triage

**H3 -- equivalent, and predicted as such in the spec before the run.** Swapping which half of the split is called `old_p` and which `new_p` cannot change behaviour, because both names are immediately added to the same set and nothing downstream distinguishes them. Recorded in `equivalents.md`.

Predicting the equivalent in the spec rather than discovering it during triage is deliberate: it makes the claim falsifiable. Had H3 been killed, the prediction would have been wrong and the reasoning above would need revisiting.

## Note on what this sweep did NOT prove

Both H1 and H4 are the original defects restored verbatim, so killing them proves the new tests detect the exact bugs that shipped. It does not prove they would detect a *different* bug in the same code -- H2 (the mirror defect) was added for that reason and was also killed.

Neither mutant addresses the more interesting question the checklist run raised: both defects were invisible to 399 passing tests and were found by a human-driven adversarial run. Mutation testing measures whether the suite constrains the code it covers; it cannot tell you the suite is aimed at the wrong place. That remains the checklist's job.
