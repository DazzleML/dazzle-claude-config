## Triage, and what the survivors have in common

| ID | Verdict | Reasoning | Killing test written |
|---|---|---|---|
| M5 | killable | The fallback for a setting with no prose became the setting's NAME. `_explain_one` branches on `if k.explain:`, so a truthy fallback silently suppresses the "explanation unavailable" path -- a packaging slip would print each setting's own name back as its meaning. | `test_a_setting_with_no_prose_gets_an_EMPTY_explanation` |
| M6 | killable | Sentence-splitting on a bare period truncates any explanation holding a version number, abbreviation or filename. None of the current eleven contain one, which is exactly why it survived. | `test_gist_ends_a_sentence_at_a_period_FOLLOWED_BY_A_SPACE` |
| M7 | killable | Off-by-one at the width boundary. No real explanation lands on it. | `test_gist_keeps_a_summary_that_is_exactly_the_width_allowed` |
| M8 | killable | Truncates to the FIRST space, collapsing every long summary to one word. The index still rendered and still fit -- it just said less. | `test_gist_trims_to_the_LAST_word_boundary_not_the_first` |
| M9 | killable | An empty setting name skips the unknown-setting error. Unreachable through argparse today because the CLI normalises `""` to `None` first -- but the guard is what makes that normalisation safe to change, and an untested guard is one the next reader simplifies away. | `test_an_empty_setting_name_is_an_ERROR_not_a_fall_through` |
| M11 | killable | Dropped `.strip()` on the opt-out environment variable. `CCS_INTERACTIVE="0 "` is what a shell script or a CI template produces, and without the strip the opt-out stops working and the run stops on a prompt -- the exact failure the branch exists to prevent. | `test_CCS_INTERACTIVE_is_honoured_with_stray_whitespace` |

**The pattern across all six: none of them could be caught through the rendered output, because the real eleven explanations never exercise the edges.** Four of the six (M6, M7, M8, and the shape of M5) live in `_gist` and `_attach_explanations` -- **pure functions whose every assertion was going through a caller's printed output**. The index rendered, fit the screen, and looked right under every mutant. Testing a pure function through its caller is how a whole function ends up unconstrained while reading as covered.

**M5 deserves its own line, because it repeats the previous release's lesson.** Mutation L4 in the v0.5.11 sweep survived by showing that proving the CURRENT settings are explained says nothing about the next one added. `explanation_gaps` was written specifically to answer L4 -- and M5 walked straight past it, because the test written alongside it asserted that *the defaults survive* a missing explanation and never asked *what the explanation itself became*. The lesson was learned in one direction and not the other. That is worth remembering more than the kill count is.

## Caveats

- **A kill proves the suite noticed *this* change, not that it tests the right thing.**
- **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** Round 2's 12/12 says these twelve specific bugs would now be caught. It says nothing about the thirteenth.
- Round 2 re-ran the *same* spec rather than generating a fresh population, so it confirms the new tests kill what they were written for -- which is the close-the-loop check, not an independent second opinion.
