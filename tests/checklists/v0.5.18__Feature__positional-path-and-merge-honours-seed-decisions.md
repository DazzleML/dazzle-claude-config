# Human Test Checklist: `ccs merge <path>` on three verbs, and merge honouring the seed decisions status honours

**Target version:** v0.5.18
**Ships with commit:** TBD (a `feat:`/`fix:` subject ending in `(v0.5.18)`)
**Companion automated tests:** 20 tests in `tests/test_positional_path.py` (12), `tests/test_one_actionable_set.py` (8); suite 635 at writing

## What this is

Two changes to `ccs merge` (one of them on `collect` and `apply` too), verified by a person at a terminal. The automated tests prove the resolver and the refusal logic; this document is for what a mock cannot show -- the words a person reads on the console, the usage line `--help` prints, a real decisions file on a real box, and that a bare `ccs merge` and `ccs status` now describe the same set of files. Anyone with the tool installed can run Sections 1 and 2 in a scratch world; Section 3 is the maintainer's own payload and is marked MANUAL.

## Prerequisites

1. **Platform.** Any. No diff tool is opened: every `merge` command below carries `--dry-run --no-launch`. Windows is where the Section 1 path spellings matter most.
2. **Isolation -- all three overrides, on every command.** `--checkout-dir` honours `CCS_CHECKOUT_DIR` and `--claude-dir` honours `CLAUDE_CONFIG_DIR`; **`--user-claude` has no environment variable and must be passed as a flag each time.** A run that reaches your real `~/.claude` or `~/claude` is a defect in this checklist, not a test.

   **cmd.exe**:
   ```cmd
   set W=%TEMP%\ccs-chk-518
   set CCS_CHECKOUT_DIR=%W%\checkout
   set CLAUDE_CONFIG_DIR=%W%\live
   set U=--no-fetch --no-color --user-claude %W%\user
   ```
   **PowerShell**:
   ```powershell
   $W = "$env:TEMP\ccs-chk-518"
   $env:CCS_CHECKOUT_DIR = "$W\checkout"
   $env:CLAUDE_CONFIG_DIR = "$W\live"
   $U = "--no-fetch", "--no-color", "--user-claude", "$W\user"
   ```
   **POSIX**:
   ```bash
   W=/tmp/ccs-chk-518
   export CCS_CHECKOUT_DIR=$W/checkout
   export CLAUDE_CONFIG_DIR=$W/live
   U="--no-fetch --no-color --user-claude $W/user"
   ```
   Every `ccs` command below is written `ccs %U% ...` (cmd), `ccs $U ...` (PowerShell), `ccs $U ...` (POSIX).

3. **Scratch world.** One checkout with three directory entries and one seeded file, and a live tree that edits every file so each one differs:

   ```
   <checkout>/ccs-manifest.json      four entries, below
   <checkout>/dotclaude/s/SAME.md    "s checkout"        (copy, entry dotclaude/s)
   <checkout>/dotclaude/t/SAME.md    "t checkout"        (copy, entry dotclaude/t)
   <checkout>/dotclaude/skills/think/SKILL.md            (copy, entry dotclaude/skills)
   <checkout>/dotclaude/SEED.md      "starter"           (seed-if-absent, entry dotclaude/SEED.md)
   <live>/s/SAME.md, t/SAME.md, skills/think/SKILL.md    each "<name> live edit"
   <live>/SEED.md                    "starter" + "mine, after delivery"
   <user>/                           empty (the decisions file is written in Section 2)
   ```
   The manifest:
   ```json
   {"manifest_version":1,
    "territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},
    "entries":[
     {"repo":"dotclaude/s","territory":"dotclaude","target":"s","strategy":"copy"},
     {"repo":"dotclaude/t","territory":"dotclaude","target":"t","strategy":"copy"},
     {"repo":"dotclaude/skills","territory":"dotclaude","target":"skills","strategy":"copy"},
     {"repo":"dotclaude/SEED.md","territory":"dotclaude","target":"SEED.md","strategy":"seed-if-absent"}]}
   ```
   **Scratch-git rules:** every git command carries `-C <checkout>` so it can never land in a real repo, and every commit carries `-c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false`. Never change global git config for a checklist run.
   ```
   git -C <checkout> init -q -b main
   git -C <checkout> -c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false add -A
   git -C <checkout> -c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false commit -qm "seed"
   ```
   Then write the live files. (A one-shot Python script that builds all of this is acceptable and shell-agnostic: `python -c` with `pathlib` and `subprocess`.)

4. **Recording a seed decision** (Section 2 needs one). Two routes; either is fine:
   - the verb: `ccs $U seed keep SEED.md --until-changed` (or `--always`)
   - by hand: write `<user>/ccs-seed-decisions.json`:
     ```json
     {"version":1,"decisions":{"SEED.md":{"decision":"keep","mode":"until-changed",
      "seed_blob":"<sha256 of the LF-normalised seed bytes>","date":"2026-09-02"}}}
     ```
     The `seed_blob` for the seed `starter\n` is `python -c "import hashlib;print(hashlib.sha256(b'starter\n').hexdigest())"`.

5. **Reset between sections:** delete `<user>/merge/ccs/` and `<user>/ccs-seed-decisions.json`.

   **cmd.exe**: `rmdir /s /q %W%\user\merge` and `del %W%\user\ccs-seed-decisions.json`
   **PowerShell**: `Remove-Item -Recurse -Force "$W\user\merge"; Remove-Item "$W\user\ccs-seed-decisions.json"`
   **POSIX**: `rm -rf "$W/user/merge" "$W/user/ccs-seed-decisions.json"`

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these five. If any fails, the release is broken.

### HV.1 -- the positional plans exactly the named file

Validates: `ccs merge <path>` resolves like `ccs diff <path>` and scopes the run.

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch think/SKILL.md`
- [ ] **Expected:** `would merge: skills/think/SKILL.md` and nothing about `SAME.md` or `SEED.md`; exit 0 or 1, never 2.
- [ ] **Why this matters:** before v0.5.18 this exact command failed with *unrecognized arguments*; if it still does, or plans more than one file, the feature did not ship.

### HV.2 -- a bare merge refuses a kept seed, visibly

Validates: merge reads the decision record status reads.

- [ ] **Steps:** record the decision (Prerequisite 4), then `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** the line `refused SEED.md -- seeded and kept-current: yours since delivery, so not merged unless you name it (ccs merge SEED.md); `ccs seed` re-asks the question`, and **no** `would merge: SEED.md`. The three copy files are still planned.
- [ ] **Why this matters:** this is the bug: a bare merge used to open a diff tool on a file status had just called "yours", with the empty starter as the base.

### HV.3 -- naming the kept seed is consent

- [ ] **Steps:** same state; `ccs $U merge --dry-run --no-launch SEED.md`
- [ ] **Expected:** `would merge: SEED.md`, and no `refused` line at all.
- [ ] **Why this matters:** the refusal must be a default, not a wall; the override the refusal names has to work.

### HV.4 -- ambiguity is listed, never guessed

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch SAME.md`
- [ ] **Expected:** on stderr, `ambiguous: 'SAME.md' matches 2 files -- name one of them:` followed by `dotclaude/s/SAME.md` and `dotclaude/t/SAME.md`; exit 2; nothing planned.
- [ ] **Why this matters:** a bare filename that silently picked the first entry was a real defect once (v0.4.1); the positional inherits the fix.

### HV.5 -- status and merge describe the same set

- [ ] **Steps:** with the decision recorded: `ccs $U status --long` (the per-seed wording is printed under `--long`), then `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** status lists `SEED.md` under *seeded* as `yours (kept until the payload's copy changes)` and reports drift in the three copy entries only; merge plans those three and prints `refused SEED.md -- seeded and kept-current ...`. Same three files, both verbs.
- [ ] **Why this matters:** the two commands disagreeing about what needs attention was how this was found.

## Section 1: the positional on all three verbs (~5 min)

### 1.1 `collect` is scoped by the positional

- [ ] **Steps:** `ccs $U collect --dry-run t/SAME.md`
- [ ] **Expected:** the dry-run names `dotclaude/t/SAME.md` and nothing else; no `s/SAME.md`, no `SKILL.md`. Exit 0 or 1.

### 1.2 `apply` is scoped by the positional

- [ ] **Steps:** `ccs $U apply --dry-run t/SAME.md`
- [ ] **Expected:** as 1.1, from the other direction. Exit 0 or 1.

### 1.3 a qualified path disambiguates

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch t/SAME.md`
- [ ] **Expected:** `would merge: t/SAME.md` only; no ambiguity line.

### 1.4 Windows spellings are tolerated

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch \think\SKILL.md` (PowerShell: quote it, `'\think\SKILL.md'`)
- [ ] **Expected:** identical to HV.1 -- backslashes and a leading slash are normalised.

### 1.5 both forms at once is refused

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch --only dotclaude/t t/SAME.md`
- [ ] **Expected:** stderr `error: name the file as a positional OR with --only, not both`; exit 2; nothing planned.

### 1.6 a typo is an error, not a quiet empty run

- [ ] **Steps:** `ccs $U merge --dry-run --no-launch nope/NOPE.md`
- [ ] **Expected:** stderr `no such file in any manifest entry: 'nope/NOPE.md' -- run ccs diff with no argument to list what differs`; exit 2. (Until v0.5.19 the positional printed its own sentence, `error: no such file 'nope/NOPE.md' in the manifest or the checkout -- ccs status lists what there is`; it now prints the one `ccs diff` prints, and says `not for this box` when the only match is tag-gated.)

### 1.7 the usage line and the hint say so

- [ ] **Steps:** `ccs merge --help | more` (any shell); then run a merge that plans four or more files (drop the decision file first) without `--dry-run` but with `--no-launch`.
- [ ] **Expected:** the usage line ends `[path]` after the options and the `path` help reads "one file, named the way `ccs diff <path>` takes it ..."; the after-merge hint reads `a long list is not one sitting: ccs merge <path> does one file, and stopping is safe`.
- [ ] **[eyes]** is the help text readable at 80 columns, and does the hint's bold survive `--no-color`?

## Section 2: the seed states (~5 min; reset between steps -- 2.3 commits a new seed to the scratch checkout, and 2.4 and 2.5 are written to run after it)

### 2.1 `open` -- customised, no decision -- still merges

- [ ] **Steps:** reset; make sure no `ccs-seed-decisions.json` exists; `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** `would merge: SEED.md` among the four; no `refused` line. (A question is genuinely pending; merge is one way to answer it.)

### 2.2 `kept-always` is refused

- [ ] **Steps:** `ccs $U seed keep SEED.md --always`; `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** `refused SEED.md -- seeded and kept-always: ...`; not planned.

### 2.3 `reopened` -- the payload moved the seed after you decided -- still merges

- [ ] **Steps:** reset; record `until-changed` against the current seed; then change the seed in the checkout and commit it (scratch-git rules): write `starter\nthe payload moved it\n` to `<checkout>/dotclaude/SEED.md`, `git -C <checkout> ... commit -qam "new seed"`; `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** `would merge: SEED.md`; no `refused` line. `ccs $U status --long` lists it as reopened (the seed changed since you decided).

### 2.4 a seed that matches its starter appears nowhere

- [ ] **Steps:** reset; make `<live>/SEED.md` byte-identical to the checkout's **current** `<checkout>/dotclaude/SEED.md` (copy the file -- after 2.3 that is the moved seed, not `starter\n`); `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** `SEED.md` is neither planned nor refused -- identical to HEAD, it never reaches merge. `ccs $U status --long` lists it as `same as the payload's copy`.

### 2.5 `untouched-old` -- the box still holds a starter the payload has since replaced -- is refused

- [ ] **Steps:** after 2.3's new-seed commit, reset the decisions file only; write exactly `starter\n` (the OLD seed) to `<live>/SEED.md`; `ccs $U merge --dry-run --no-launch`
- [ ] **Expected:** `refused SEED.md -- seeded and untouched-old: ...`; not planned. `ccs $U status --long` lists it as untouched-old and offers `--reseed`. (This box never edited the starter; taking the new one is a reseed, not a merge -- and merge says so rather than opening a tool on it.)

## Section 3: the real thing (MANUAL, maintainers only)

*External testers skip this section; it needs the maintainer's own payload.*

- [ ] On the box where this was found, with the real payload checkout and **no overrides**, run `ccs merge --dry-run --no-launch` -- **`--dry-run` is not optional here**: that workspace holds a real, deliberately held merge run, and a bare `ccs merge` there is exactly what this release stops from doing harm.
- [ ] **Expected:** `refused settings.local.json -- seeded and kept-current: yours since delivery, ...` and `would merge:` lines for the same entries `ccs status` reports as drifting -- and only those. Before v0.5.18 this run planned six files against status's two.
- [ ] Then `ccs merge --dry-run --no-launch settings.local.json` plans it (consent by naming), with no refused line. Do not proceed past `--dry-run` unless you mean to merge it.

## What the automated tests DON'T cover

- The console wording as a person reads it: whether `refused ... seeded and kept-current: yours since delivery` says the right thing to someone who did not write it.
- `--help` and the usage line as argparse renders them, at real terminal widths.
- A real `ccs-seed-decisions.json` written by `ccs seed keep` on a real box, with real seeds (`settings.local.json`, the machine and platform templates) -- Section 3.
- Windows path spellings typed at a prompt, with the shell's own quoting in the way.
- That a diff tool does **not** launch for a refused seed -- the tests pass `--no-launch`; a person watching the screen is the only proof.
- Tag-gated seeds and directory seeds: unchanged by this release (still planned); no scratch world here exercises them.

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and its stdout/stderr.
3. Keep `<user>/ccs-seed-decisions.json` and the `merge/ccs` workspace from the run.
4. File an issue referencing this checklist and v0.5.18.
