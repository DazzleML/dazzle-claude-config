## What this is

Hand-runnable verification of the three user-visible changes since the MVP checklist: (1) **implicit layout** — any bare `~/.claude` mirror works as a payload without a manifest; (2) **deny-aware verbs** — deny-matched files are annotated protection, not perpetual drift/alarm; (3) **CLI UX** — options accepted after the verb, real console scripts, alpha display string.

## Prerequisites

`pip install -e .` from the repo root (or the released package) so the real `ccs` console script is on PATH. Fixture setup (any shell; nothing touches real config):

**PowerShell**:
```powershell
$env:CCS_FIX = "$env:TEMP\ccs-021"
if (Test-Path $env:CCS_FIX) { Remove-Item -Recurse -Force $env:CCS_FIX }
New-Item -ItemType Directory -Force "$env:CCS_FIX\claude","$env:CCS_FIX\user","$env:CCS_FIX\mirror\skills\myskill" | Out-Null
Set-Content "$env:CCS_FIX\mirror\CLAUDE.md" "# my memory"
Set-Content "$env:CCS_FIX\mirror\skills\myskill\SKILL.md" "skill"
git -C "$env:CCS_FIX\mirror" init -q -b main; git -C "$env:CCS_FIX\mirror" add -A; git -C "$env:CCS_FIX\mirror" -c user.email=t@t -c user.name=t commit -q -m mirror
```

**POSIX**:
```bash
export CCS_FIX=/tmp/ccs-021 && rm -rf "$CCS_FIX"
mkdir -p "$CCS_FIX/claude" "$CCS_FIX/user" "$CCS_FIX/mirror/skills/myskill"
printf '# my memory\n' > "$CCS_FIX/mirror/CLAUDE.md"
printf 'skill\n' > "$CCS_FIX/mirror/skills/myskill/SKILL.md"
git -C "$CCS_FIX/mirror" init -q -b main && git -C "$CCS_FIX/mirror" add -A && git -C "$CCS_FIX/mirror" -c user.email=t@t -c user.name=t commit -q -m mirror
```

Shorthand: `CCS = ccs <verb> --checkout-dir <CCS_FIX>/mirror --claude-dir <CCS_FIX>/claude --user-claude <CCS_FIX>/user` (note: flags AFTER the verb — that's part of what you're testing).

## High-Value Verification (~4 minutes)

### HV.1 — Bare mirror applies without a manifest

- [ ] **Steps:** `CCS apply` (per shorthand — the mirror has NO ccs-manifest.json)
- [ ] **Expected:** a `note: no ccs-manifest.json -- using implicit ~/.claude layout (2 standard surfaces detected)` line; `CLAUDE.md` and `skills/myskill/SKILL.md` land in the fixture claude dir; exit 0; second run says `nothing to do`.
- [ ] **Why this matters:** the headline v0.2.0 promise — anyone's pushed `~/.claude` works.

### HV.2 — Non-config repo refuses clearly

- [ ] **Steps:** make an empty dir with just a `src/` inside; `ccs status --checkout-dir <that dir> --claude-dir <CCS_FIX>/claude --user-claude <CCS_FIX>/user`
- [ ] **Expected:** one clean stderr line naming the expected markers (CLAUDE.md, skills, commands, agents, settings.json); exit 2; NO implicit-layout note.

### HV.3 — Deny-aware: protection is not drift

> *Protected files can never sync, so their presence is the intended state -- they must not be reported as drift, while genuine credential content still alarms.*

- [ ] **Steps:** create `<CCS_FIX>/claude/skills/.credentials.json` (any content — note: inside a TRACKED dir; files at the territory root are outside the allowlist and invisible to every verb); `CCS status`; then `CCS collect`.
- [ ] **Expected:** status prints `note: denied, never syncs: ...` AND `status: clean` with exit 0; collect notes it at exit 0 and the file does NOT appear in the mirror. Then plant `key = sk-ant-` + 24 letters in `<CCS_FIX>/claude/skills/leak.md` → collect REFUSES with exit 1 (content alarms still alarm).
- [ ] **Apply direction:** create `<CCS_FIX>/mirror/skills/.credentials.json`; `CCS apply` → `REFUSED (deny-list .credentials.json -- remove it from the payload repo): ...`, exit 1, and the file does NOT land in the fixture claude dir. A denied file IN the payload is an anomaly (unlike the live-side note above, which is the guard working as intended).
- [ ] **Why this matters:** the perpetual "drift in 1 entry" first impression is gone, without weakening the actual alarm — and the deny wall now stands in BOTH directions (an adversarial test run found `apply` had none -- see `results/v0.2.1__Feature__tester-unbounded-run-02.md`).

### HV.4 — Flags after the verb + real console scripts

- [ ] **Steps:** exactly as typed by a human: `ccs status --checkout-dir <CCS_FIX>/mirror --claude-dir <CCS_FIX>/claude --user-claude <CCS_FIX>/user`; also `ccs --version` and `dazzle-claude-config --version`.
- [ ] **Expected:** no "unrecognized arguments"; both entry points print `ccs ALPHA 0.2.1 (...)` — the alpha display with plain pip version underneath.

## Section 1: Edge details (~5 min)

- [ ] **1.1 Mixed positions**: `ccs --claude-dir <CCS_FIX>/claude status --checkout-dir <CCS_FIX>/mirror --user-claude <CCS_FIX>/user` — pre- and post-verb flags combine; post-verb wins if both given.
- [ ] **1.1b `CCS_CHECKOUT_DIR`**: set it to the mirror, then run `ccs status --claude-dir <CCS_FIX>/claude --user-claude <CCS_FIX>/user` with NO `--checkout-dir` — same result. Then pass `--checkout-dir` pointing elsewhere: the flag wins. Unset a bogus value and confirm the not-found error names the env var.
- [ ] **1.1c Fresh-clone importability**: `git clone` the repo to a temp dir and `python -c "import dazzle_claude_config.secrets"` — must succeed (guards the `.gitignore` `*secret*` regression that made the published repo unimportable).
- [ ] **1.2 Implicit collect round-trip**: add a file in the fixture claude skills dir → `CCS collect` copies it INTO the mirror at root layout (`skills/...`, no `dotclaude/` prefix); `git -C <mirror> status` shows it (commit it yourself — ccs never commits).
- [ ] **1.3 Explicit manifest still wins**: run against the real payload checkout (READ-ONLY: `status` only) — no implicit note appears.
- [ ] **1.5 Output readability + color** (the part mocks can't judge): in a real terminal, `CCS status` clean and drift cases — is the verdict line actionable without docs? Does `protected` read as the guard working rather than an error? Is the branch line human ("on main, in sync with origin/main")? Then confirm color renders in your shells (Windows Terminal, cmd, PowerShell, VS Code) and that `ccs status --no-color`, `NO_COLOR=1 ccs status`, and `ccs status | cat` all emit zero escape codes.
- [ ] **1.4 settings.json in implicit mode**: add a `settings.json` to the mirror → `CCS apply` copies it over the fixture's (this is INTENDED for owner-mirrors; confirm the README/alpha note frames it).
