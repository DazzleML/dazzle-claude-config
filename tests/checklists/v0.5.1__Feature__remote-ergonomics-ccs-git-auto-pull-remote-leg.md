# Human Test Checklist: v0.5.1 -- Remote Ergonomics (`ccs git`, `auto_pull`, the remote status leg)

**Target version:** 0.5.1
**Ships with commit:** TBD (feature wave for issues #25 and #22, plus direction-first verb help)
**Companion automated tests:** 314 total; 26 new in `tests/test_remote_ergonomics.py` (argv split 7, git verb 4, auto_pull 6, remote leg 3, formatters 2, help 1, cross-check 1, plus fixture plumbing), 4 updated assertions in `tests/test_remote_awareness.py`

## What this is

v0.5.1 lets `status` act on what it sees instead of only describing it. Three surfaces: `ccs git <anything>` runs git in the checkout from any directory (argv passed through verbatim, exit code preserved); `auto_pull` makes `status` fast-forward a behind checkout before reporting drift (strictly ff-only, opt-in); and `status` grows a labelled `remote` leg naming the host and pull state. A fourth, small surface: `collect`/`apply` help lines now lead with their direction. This checklist covers what the 26 automated tests cannot: real pagers and credential prompts through the passthrough, TTY color, cmd.exe rendering, and the real-fleet loop.

## Prerequisites

1. `ccs --version` reports 0.5.1 (or the editable install at the wave's commit).
2. A scratch fleet under the temp directory -- NEVER the real checkout. Build it once:

   **cmd.exe**:
   ```cmd
   set SCRATCH=%TEMP%\ccs-051-check
   mkdir %SCRATCH% && cd /d %SCRATCH%
   git init -q --bare -b main remote.git
   git clone -q remote.git other
   cd other && mkdir dotclaude
   echo {"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},"entries":[{"repo":"dotclaude/F.md","territory":"dotclaude","target":"F.md","strategy":"copy"}]} > ccs-manifest.json
   echo a> dotclaude\F.md
   git add -A && git commit -qm seed1 && echo b>> dotclaude\F.md && git commit -qam seed2 && git push -qu origin main
   cd .. && git clone -q remote.git checkout && mkdir live user
   copy checkout\dotclaude\F.md live\F.md >nul
   ```

   **PowerShell**:
   ```powershell
   $S = "$env:TEMP\ccs-051-check"; New-Item -ItemType Directory -Force $S | Out-Null; Set-Location $S
   git init -q --bare -b main remote.git
   git clone -q remote.git other; Set-Location other; New-Item -ItemType Directory dotclaude | Out-Null
   '{"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},"entries":[{"repo":"dotclaude/F.md","territory":"dotclaude","target":"F.md","strategy":"copy"}]}' | Set-Content -Encoding ascii ccs-manifest.json
   "a" | Set-Content dotclaude\F.md; git add -A; git commit -qm seed1
   "b" | Add-Content dotclaude\F.md; git commit -qam seed2; git push -qu origin main
   Set-Location ..; git clone -q remote.git checkout; New-Item -ItemType Directory live,user | Out-Null
   Copy-Item checkout\dotclaude\F.md live\F.md
   ```

   **POSIX**:
   ```bash
   S=/tmp/ccs-051-check && mkdir -p "$S" && cd "$S"
   git init -q --bare -b main remote.git
   git clone -q remote.git other && cd other && mkdir dotclaude
   printf '%s' '{"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},"entries":[{"repo":"dotclaude/F.md","territory":"dotclaude","target":"F.md","strategy":"copy"}]}' > ccs-manifest.json
   echo a > dotclaude/F.md && git add -A && git commit -qm seed1
   echo b >> dotclaude/F.md && git commit -qam seed2 && git push -qu origin main
   cd .. && git clone -q remote.git checkout && mkdir live user
   cp checkout/dotclaude/F.md live/F.md
   ```

3. Every `ccs` call below uses the scratch fleet flags; `<SCRATCH>` means the directory above:

   ```
   ccs --checkout-dir <SCRATCH>/checkout --claude-dir <SCRATCH>/live --user-claude <SCRATCH>/user ...
   ```

   Abbreviated below as `ccs* ...`.

4. **To make the scratch checkout "behind"** (used by several tests): commit and push from `other`:

   ```
   git -C <SCRATCH>/other commit -am advance --allow-empty && git -C <SCRATCH>/other push -q
   ```

5. **Reset between sections**: `git -C <SCRATCH>/checkout reset -q --hard origin/main && git -C <SCRATCH>/checkout pull -q` and delete `<SCRATCH>/user/ccs-config.json` if created.

## High-Value Verification (~5 minutes)

### HV.1 -- `ccs git` runs git in the checkout, from anywhere

Validates: the pre-argparse passthrough and checkout resolution (#25).

- [ ] **Steps:** from any directory OUTSIDE the scratch fleet:
  1. `ccs* git log --oneline -2`
  2. `ccs* git` (bare)
- [ ] **Expected:** (1) the scratch repo's two seed commits -- git's own output, untouched; (2) the resolved checkout path plus a one-line hint, exit 0.
- [ ] **Why this matters:** this is the verb everything else's hints point at; if resolution or passthrough is wrong, every "ccs git pull" suggestion in the UI is a lie.

### HV.2 -- git's flags survive the passthrough

Validates: everything after `git` belongs to git (the dazzlecmd split).

- [ ] **Steps:** `ccs* git log --oneline --no-color -1` then `echo exit: %ERRORLEVEL%` (cmd) / `echo "exit: $?"` (POSIX/PS `$LASTEXITCODE`)
- [ ] **Expected:** git accepts `--no-color` as ITS flag (no ccs error about argument order); exit 0. Then `ccs* git rev-parse -q --verify no-such-ref` exits nonzero (code passthrough).
- [ ] **Why this matters:** if ccs eats git's flags, the verb silently runs a different git command than the user typed.

### HV.3 -- `auto_pull` closes the loop in one run

Validates: fetch -> ff -> compare ordering (#25's core promise).

- [ ] **Steps:**
  1. Make the checkout behind (Prerequisite 4).
  2. Write `<SCRATCH>/user/ccs-config.json` containing `{"auto_pull": true}`.
  3. `ccs* status`
- [ ] **Expected:** the remote line reads `... was 1 behind -- fast-forwarded`; the drift table below it describes the POST-pull state; `git -C <SCRATCH>/checkout log --oneline -1` shows the other machine's commit.
- [ ] **Why this matters:** the whole feature is "one command instead of five"; if the compare runs before the ff, status reports a world that no longer exists.

### HV.4 -- divergence is refused, loudly and harmlessly

Validates: the ff-only safety contract.

- [ ] **Steps:**
  1. Reset (Prerequisite 5), make the checkout behind, then commit locally in the checkout: `git -C <SCRATCH>/checkout commit --allow-empty -qm local`
  2. `ccs* status --pull`
- [ ] **Expected:** `fast-forward refused` + `diverged` on the remote line; `git -C <SCRATCH>/checkout status` shows NO merge in progress, no changed files; exit code 1 (behind is drift).
- [ ] **Why this matters:** an auto-pull that merges would hand users robot-made conflicts; this is the line between convenience and damage.

### HV.5 -- the remote leg reads right

Validates: #22's format on a real terminal.

- [ ] **Steps:** reset, then `ccs* status` in a color-capable terminal.
- [ ] **Expected:** first line `remote    <path-or-host>: main, in sync`, second line `checkout  <path>  (on main)`; with the real dev-box config (`ccs status`, no scratch flags) the remote line shows `github.com/<owner>/<repo>` parsed from the https URL.
- [ ] **Why this matters:** this line is now the first thing every fleet user reads; if the host parse or layout is off, the flagship QOL change reads as a regression.

### HV.6 -- the verbs finally say which way they point

- [ ] **Steps:** `ccs -h`
- [ ] **Expected:** `collect ... live -> checkout: ...`, `apply ... checkout -> live: ...`, a `git` verb line, and the epilog sentence "Directions are named from the payload's side". Arrows are ASCII `->` and render cleanly in cmd.exe (codepage 437).
- [ ] **Why this matters:** this was the user complaint that started the wave -- collect/apply direction shouldn't need memorizing.

## Section 1: `ccs git` passthrough details (~5 min)

### 1.1 Pager behavior through the passthrough
- [ ] **Steps:** in a REAL interactive terminal (not piped): `ccs* git log` (no -n limit; add commits first if needed).
- [ ] **Expected:** git's pager (less) engages exactly as it would after `cd`; `q` exits cleanly; no ccs traceback around the pager.
- [ ] **Check:** run once from cmd.exe and once from bash/WSL -- the stdio inheritance differs and only a human sees it.

### 1.2 Globals before the verb still work
- [ ] **Steps:** `ccs --no-color --checkout-dir <SCRATCH>/checkout git log --oneline -1`
- [ ] **Expected:** works identically; the ccs globals were consumed, everything after `git` went to git.

### 1.3 Refusals
- [ ] **Steps:** `ccs --checkout-dir <SCRATCH>/live git status` (a plain dir, not a repo)
- [ ] **Expected:** exit 2 and a clear refusal on stderr -- either `not a git repository` or the home-repo guard message if your temp dir sits inside a repo tracking `~`. Never a traceback.

### 1.4 `ccs git -h` belongs to git
- [ ] **Steps:** `ccs* git -h`
- [ ] **Expected:** GIT's help (for `git` itself), not ccs's -- everything after the verb is git's, help flags included.

## Section 2: auto_pull details (~7 min)

### 2.1 `--pull` works without the config key
- [ ] **Steps:** reset; make behind; `ccs* status --pull` (no ccs-config.json).
- [ ] **Expected:** `was 1 behind -- fast-forwarded`.

### 2.2 `--no-pull` beats the config
- [ ] **Steps:** reset; make behind; config `{"auto_pull": true}`; `ccs* status --no-pull`.
- [ ] **Expected:** `1 behind -- ccs git pull` on the remote line, checkout HEAD unchanged.

### 2.3 `CCS_AUTO_PULL` env override
- [ ] **Steps** (pick your shell): reset; make behind; no config file; set the env var, then `ccs* status`:

  **cmd.exe**: `set CCS_AUTO_PULL=true`
  **PowerShell**: `$env:CCS_AUTO_PULL = "true"`
  **POSIX**: `export CCS_AUTO_PULL=true`
- [ ] **Expected:** fast-forwarded, same as the config key. Unset afterwards (`set CCS_AUTO_PULL=` / `Remove-Item Env:\CCS_AUTO_PULL` / `unset CCS_AUTO_PULL`).

### 2.4 Dirty-file refusal is git's own message
- [ ] **Steps:** reset; make behind with a change to `dotclaude/F.md`; then dirty the SAME file in the checkout working tree (edit `<SCRATCH>/checkout/dotclaude/F.md`, do not commit); `ccs* status --pull`.
- [ ] **Expected:** `fast-forward refused: <git's own first line>` (about overwritten local changes); working tree edit still present afterwards, untouched.

### 2.5 `--no-fetch` suppresses the pull
- [ ] **Steps:** reset; make behind; config on; `ccs* status --no-fetch`.
- [ ] **Expected:** no ff (HEAD unchanged); remote line labelled `as last fetched`.

## Section 3: remote leg details (~5 min)

### 3.1 Color tones on a real TTY
- [ ] **Steps:** run three states in a color terminal: in sync (reset), behind (make behind, `--no-pull`), just-pulled (`--pull`).
- [ ] **Expected:** dim/neutral when in sync; yellow when behind or diverged; green on `was N behind -- fast-forwarded`. Plain when piped or with `--no-color`.

### 3.2 URL forms
- [ ] **Steps:** `git -C <SCRATCH>/checkout remote set-url origin git@github.com:o/r.git` then `ccs* status --no-fetch`; repeat with `ssh://git@host:2222/o/r.git`; then restore the file path URL.
- [ ] **Expected:** `github.com/o/r`, then `host:2222/o/r`, then the raw filesystem path (brutal fallback -- unparseable URLs are shown as-is, never guessed).

### 3.3 `--compact`, no-upstream, detached
- [ ] **Steps:** `ccs* status --compact` (remote line still present); `git -C <SCRATCH>/checkout checkout -q --detach && ccs* status --no-fetch`; then `git -C <SCRATCH>/checkout checkout -q main`.
- [ ] **Expected:** compact keeps the leg; detached shows `detached HEAD (not on a branch)`; no crashes.

## Section 4: MANUAL -- the real fleet (operator only, not for test agents)

### 4.1 `ccs git push` against the real payload (auth prompt)
- [ ] After the next real payload commit: `ccs git push` from any directory. Credential helper / SSH agent behaves exactly as `git -C <checkout> push` would. Push lands.

### 4.2 A real behind-state, end to end
- [ ] After another box pushes to the payload: `ccs status` (with `auto_pull` on, or `--pull`) fast-forwards the real checkout and reports post-pull drift in one run.

### 4.3 The aktuldjr flip uses only the new loop
- [ ] Run the aktuldjr layered-CLAUDE.md flip with `ccs status --pull` + `ccs git` only -- never cd'ing into the checkout. Note any moment the loop still forces a cd; each one is a v0.5.2 candidate.

- Error-message QUALITY judgments -- the refusals are asserted present, not judged helpful
