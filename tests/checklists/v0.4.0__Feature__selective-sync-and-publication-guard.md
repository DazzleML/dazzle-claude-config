# Human Test Checklist: Selective Sync and the Publication Guard

**Target version:** 0.4.0
**Ships with commit:** TBD (staged: `feat: selective sync -- collect can send part of a payload, and hold back what it has never seen (v0.4.0)`)
**Companion automated tests:** 140 total; the ones specific to this feature are 16 in `tests/test_collect.py` (7 new: 3 for `--only`, 4 for `hold_additions`). For context, `tests/test_merge.py` holds 44 and the remaining ~80 cover apply/status/cli/manifest/edge cases.

## What this is

v0.4.0 adds three related things to `collect`: an `--only <prefix>` scope filter, a `hold_additions` manifest key that stops `collect` from creating files the checkout has never tracked (with `--add` as the escape hatch), and editor/OS clutter in the default exclusions. The failure this feature exists to prevent is **silent over-publication** — a `collect` toward a published repo copying a personal file nobody meant to share, exiting 0, and reporting success. No exit code reports that failure, which is why a human has to run this.

Anyone can run this checklist; it never touches your real `~/.claude` or `~/claude`.

## Prerequisites

1. `ccs` installed from this repo at **0.4.0** (`pip install -e .` from the repo root).
2. git available on PATH.
3. Nothing else — the whole checklist runs in a throwaway directory.

### One-time setup: define the test root

**cmd.exe**:
```cmd
set TESTROOT=%TEMP%\ccs-checklist
```

**PowerShell**:
```powershell
$TESTROOT = "$env:TEMP\ccs-checklist"
```

**POSIX**:
```bash
TESTROOT=/tmp/ccs-checklist
```

> Blocks below are written with `$TESTROOT`, which works verbatim in **PowerShell and POSIX**. **cmd.exe** users: substitute `%TESTROOT%`. Forward slashes in paths are fine on Windows for every command here.

### Build the sandbox (run once, and again to reset between sections)

Cross-shell (uses `git` + `python` only). Delete the old root first when resetting — see Cleanup for per-shell delete commands.

```bash
python -c "import os,json,pathlib; R=os.environ.get('TESTROOT') or r'$TESTROOT'; P=pathlib.Path(R); \
(P/'live/dotclaude/skills/alpha').mkdir(parents=True); \
(P/'live/dotclaude/commands').mkdir(parents=True); \
(P/'live/dotclaude/agents').mkdir(parents=True); \
(P/'payload/dotclaude/skills/alpha').mkdir(parents=True); \
(P/'payload/dotclaude/commands').mkdir(parents=True); \
(P/'live/dotclaude/skills/alpha/SKILL.md').write_text('alpha v2\n'); \
(P/'live/dotclaude/skills/newskill.md').write_text('brand new\n'); \
(P/'live/dotclaude/commands/personal-note.md').write_text('mine only\n'); \
(P/'live/dotclaude/commands/shared.md').write_text('for everyone\n'); \
(P/'live/dotclaude/agents/helper.md').write_text('an agent\n'); \
(P/'payload/dotclaude/skills/alpha/SKILL.md').write_text('alpha v1\n'); \
(P/'payload/dotclaude/commands/existing.md').write_text('already tracked\n'); \
(P/'payload/ccs-manifest.json').write_text(json.dumps({'manifest_version':1, \
 'territories':{'dotclaude':{'root_var':'CLAUDE_DIR','repo_dir':'dotclaude'}}, \
 'entries':[{'repo':'dotclaude/skills','territory':'dotclaude','target':'skills','strategy':'copy'}, \
            {'repo':'dotclaude/commands','territory':'dotclaude','target':'commands','strategy':'copy'}, \
            {'repo':'dotclaude/agents','territory':'dotclaude','target':'agents','strategy':'copy'}, \
            {'repo':'dotclaude/CLAUDE.seed.md','territory':'dotclaude','target':'CLAUDE.md','strategy':'seed-if-absent'}], \
 'collect_exclude':['commands/personal-*.md'],'deny':[], 'hold_additions':True},indent=2)); \
print('sandbox at', R)"
git -C "$TESTROOT/payload" init -q
git -C "$TESTROOT/payload" add -A
git -C "$TESTROOT/payload" -c user.email=t@t -c user.name=t commit -qm seed
```

> cmd.exe note: the `python -c` line reads `TESTROOT` from the environment, so `set TESTROOT=...` first and it works unchanged.

**Every ccs command below carries all three isolation flags.** This is what keeps your real config out of reach — `--user-claude` matters even though the manifest has no userclaude territory, because backups default under it:

```bash
ccs <verb> --checkout-dir $TESTROOT/payload --claude-dir $TESTROOT/live/dotclaude --user-claude $TESTROOT/live/userclaude
```

(Abbreviated below as `ccs <verb> <FLAGS>`.)

## High-Value Verification (~5 minutes)

### HV.1 — The version gate

Validates: the guard exists at all in the installed build.

- [ ] **Steps:** `ccs --version`
- [ ] **Expected:** `0.4.0` or later.
- [ ] **Why this matters:** on any older ccs, `hold_additions` is an unknown manifest key and is **silently ignored** — the guard is absent with no warning, which is the fail-open this release closes. Any team standardizing on the guard must also standardize the minimum version.

### HV.2 — New files are withheld, by name (AC-4)

Validates: the publication guard's core behavior.

- [ ] **Steps:** `ccs collect <FLAGS> --dry-run`
- [ ] **Expected:**
  - `would copy: dotclaude/skills/alpha/SKILL.md` (tracked file still updates)
  - `WITHHELD: 2 files the checkout does not have yet -- NOT copied`, listing `dotclaude/skills/newskill.md` and `dotclaude/commands/shared.md` (the `commands` entry is tracked in the payload via `existing.md`, so its new file is withheld rather than adopted), followed by the remediation line naming `--add` and `collect_exclude`
  - an `ADOPTING: dotclaude/agents ...` line — that entry is deliberately unseeded in the payload, so its files bypass the gate (the exemption is Section 2.3's subject)
  - `personal-note.md` appears **nowhere** (excluded, not withheld — different mechanisms)
- [ ] **Why this matters:** if WITHHELD is absent or unnamed, the guard is decorative — the operator can't act on what they can't see.

### HV.3 — `--add` is a working escape hatch (AC-5)

- [ ] **Steps:** `ccs collect <FLAGS> --add --dry-run`
- [ ] **Expected:** both previously-withheld files now show `would copy`; no WITHHELD block.
- [ ] **Why this matters:** a gate with no gate-opening is a wall; deliberate publication must stay a one-flag operation.

### HV.4 — `--only` scopes, and a bad prefix is loud (AC-1, AC-2)

- [ ] **Steps:**
  1. `ccs collect <FLAGS> --only dotclaude/skills --add --dry-run`
  2. `ccs collect <FLAGS> --only dotclaude/typo --dry-run`
- [ ] **Expected:** (1) touches only `skills/` paths — nothing from `commands/`; (2) prints `warning: --only 'dotclaude/typo' matched no manifest entries` and does not claim success silently.
- [ ] **Why this matters:** a typo'd `--only` that exits 0 quietly is indistinguishable from "already in sync."

### HV.5 — Exclusion, checked with a known-answer control (AC-8, collect side)

- [ ] **Steps:** run `ccs status <FLAGS> --long`, then check both directions:
  - the excluded file is absent — search for `personal-note`
  - the control IS present — search for `shared.md`
- [ ] **Expected:** `shared.md` found; `personal-note` not found.
- [ ] **Why this matters:** the control proves your search can detect presence. During development, an unanchored regex "verified" exclusion by matching inside unrelated filenames — a check that can't find the control is proving nothing.

## Section 1: `--only` details (~5 min)

### 1.1 Unscoped run is unchanged by the flag's existence

- [ ] **Steps:** `ccs collect <FLAGS> --add --dry-run` (no `--only`)
- [ ] **Expected:** all entries processed — both `skills/` and `commands/` paths appear.

### 1.2 Prefix is entry-granular, not file-granular

- [ ] **Steps:** `ccs collect <FLAGS> --only dotclaude/skills/alpha --dry-run`
- [ ] **Expected:** the no-match warning. `--only` matches **entry repo paths** (`dotclaude/skills`), not files inside them. This is a documented limit (sub-entry selection is issue #7's remaining scope), but verify the failure is loud, not silent.

## Section 2: the publication guard (~10 min)

### 2.1 Real run (not dry) withholds on disk, not just in prose

- [ ] **Steps:** `ccs collect <FLAGS>` (no `--dry-run`, no `--add`), then check the payload tree.
- [ ] **Check** (pick your shell):
  - **cmd.exe**: `dir %TESTROOT%\payload\dotclaude\skills` and `if exist %TESTROOT%\payload\dotclaude\skills\newskill.md echo LEAKED`
  - **PowerShell**: `Test-Path $TESTROOT/payload/dotclaude/skills/newskill.md` → must be `False`
  - **POSIX**: `test -f $TESTROOT/payload/dotclaude/skills/newskill.md && echo LEAKED || echo ok`
- [ ] **Expected:** `alpha/SKILL.md` in the payload now reads `alpha v2` (updated); `newskill.md` does **not exist** in the payload.

### 2.2 Back-compat: a manifest without the key (AC-11)

- [ ] **Steps:** edit `$TESTROOT/payload/ccs-manifest.json`, delete the `"hold_additions": true` line, re-run `ccs collect <FLAGS> --dry-run`.
- [ ] **Expected:** no WITHHELD block; new files show `would copy` — exactly the pre-0.4.0 additive behavior. Both real-world payload repos predate this key; a default of "hold" would have silently frozen them.
- [ ] **Reset:** `git -C $TESTROOT/payload checkout -- ccs-manifest.json` — the committed copy carries the key, so this restores the guard.

### 2.3 Adoption: a zero-tracked entry admits files despite the gate (AC-6)

**Rebuild the sandbox first** — Section 2.1's real run adopts the `agents` entry, consuming this test's precondition. The `agents` entry is the sandbox's deliberate zero-tracked case: the payload has no `dotclaude/agents/` directory at all.

- [ ] **Steps:** rebuild, then `ccs collect <FLAGS> --only dotclaude/agents --dry-run`
- [ ] **Expected:** `ADOPTING: dotclaude/agents -- the checkout carried nothing here, so its files are being added`, and `helper.md` shows `would copy` **without** `--add`.
- [ ] **Why:** the first collect against a fresh payload would otherwise withhold everything and exit 0 — a silent no-op, the exact failure shape the gate exists to prevent, pointed the other way.

### 2.4 Seed-if-absent entries under the gate (AC-7) — **never verified anywhere; may find a bug**

- [ ] **Steps:** create the seed source in live:
  - cross-shell: `python -c "import os,pathlib; pathlib.Path(os.environ.get('TESTROOT') or r'$TESTROOT','live/dotclaude/CLAUDE.md').write_text('memory\n')"`
  - then `ccs collect <FLAGS> --dry-run`
- [ ] **Expected:** the seed entry appears **nowhere** in collect's output — not copied, not withheld. Seed entries are apply-direction only: `diff_all` iterates copy-strategy entries exclusively, so the gate never sees them. (Verified once in a sandbox on 2026-08-21; this step re-confirms it on your machine.)
- [ ] **If it IS withheld or copied:** that is a genuine AC-7 failure. Capture the output and file an issue referencing this section.

### 2.5 Ordering with the two-way refusal — the guard report can be masked

- [ ] **Steps:** make `alpha/SKILL.md` differ on **both** sides: edit it in live AND in the payload (different edits), commit the payload edit, then `ccs collect <FLAGS> --dry-run`.
- [ ] **Expected (per design):** `REFUSING: 1 file changed on BOTH sides...` — and note whether the WITHHELD block still prints.
- [ ] **KNOWN DEFECT (≤0.4.0, HIGH):** no REFUSING appears at all. The two-way guard checks `is_file()` on each entry's target and skips every directory-shaped entry, so it has only ever protected single-file entries — a real collect here silently overwrites the payload's diverged edit and exits 0. Found by this step in run-03 (2026-08-21); fix targeted at 0.4.1. On 0.4.0, expect exactly that failure.
- [ ] **Why this matters:** during development, the refusal fired first and the run never reached the gate report. That masking is currently accepted behavior, but a tester should know the WITHHELD list is **not** shown on a refused run — resolve the refusal first, then re-check what would be withheld.
- [ ] **Reset:** rebuild the sandbox.

## Section 3: exclusion semantics (~10 min)

### 3.1 Glob breadth — a pattern matches more than it looks like (AC-9's sharp edge)

Patterns match the target-relative path, the **bare filename**, and **any directory segment**.

- [ ] **Steps:** the sandbox's `commands/personal-*.md` pattern is path-anchored; this test uses a *bare-name* pattern to show the difference. Append `"scratch.md"` to the manifest's `collect_exclude`, create `$TESTROOT/live/dotclaude/skills/scratch.md` AND `$TESTROOT/live/dotclaude/commands/scratch.md`, then run `ccs status <FLAGS> --long`.
- [ ] **Expected:** **both** files are invisible — a bare-filename pattern excludes that name in *every* entry. If you meant only one directory, you must path-anchor the pattern.
- [ ] **Reset:** remove the pattern and the two files, or rebuild.

### 3.2 Exclusion is symmetric and covers all verbs (AC-8)

- [ ] **Steps:** put `personal-note.md` in the **payload** too (it's excluded from live's side already): `python -c "import os,pathlib; pathlib.Path(os.environ.get('TESTROOT') or r'$TESTROOT','payload/dotclaude/commands').mkdir(parents=True,exist_ok=True); pathlib.Path(os.environ.get('TESTROOT') or r'$TESTROOT','payload/dotclaude/commands/personal-note.md').write_text('divergent copy\n')"` — then run all three:
  1. `ccs status <FLAGS> --long`
  2. `ccs apply <FLAGS> --dry-run`
  3. `ccs merge <FLAGS> --dry-run`
- [ ] **Expected:** `personal-note.md` appears in **none** of the three outputs — not as drift, not as apply-pending, not as a merge candidate. Exclusion lives in the diff engine, so it governs every verb identically.
- [ ] **Reset:** rebuild the sandbox.

### 3.3 Deny + exclude overlap (AC-12) — **never verified anywhere; exploratory**

- [ ] **Steps:** add `"personal-note.md"` to the manifest's `deny` list (it already matches `collect_exclude`), re-run `ccs status <FLAGS> --long` and `ccs collect <FLAGS> --dry-run`.
- [ ] **Record what you see:** as of the design analysis, exclusion is applied before the deny check, so the expected outcome is *silent invisibility* (no `REFUSED (deny-list ...)` line, no `protected` entry). That means a deny rule shadowed by an exclusion gives **no signal** that the stronger guard never evaluated. This is a known, honestly-open gap — capture the actual output either way and attach it to the issue if it differs.

## Section 4: rendering and defaults (~5 min)

### 4.1 WITHHELD/ADOPTING on a real terminal vs piped

- [ ] **Steps:** run HV.2's command directly in a terminal, then piped:
  - **cmd.exe**: `ccs collect <FLAGS> --dry-run | findstr WITHHELD`
  - **PowerShell**: `ccs collect <FLAGS> --dry-run | Select-String WITHHELD`
  - **POSIX**: `ccs collect <FLAGS> --dry-run | grep WITHHELD`
- [ ] **Expected:** on the TTY, WITHHELD renders in yellow and ADOPTING in cyan with no garbled escape codes (Windows Terminal and legacy conhost both); piped output is plain text, no ANSI litter. `--no-color` and `NO_COLOR=1` also strip color.

### 4.2 Built-in defaults exclude editor clutter (implicit manifest only)

- [ ] **Steps:** create a **manifest-less** payload: new dir, `git init`, then `mkdir` a `skills` directory inside it — a zero-commit empty repo raises `ManifestError` before the exclusion logic is ever reached. Plus a live tree containing `skills/thing/.vscode/settings.json` and `skills/thing/SKILL.md`; run `ccs status` against it with isolation flags.
- [ ] **Expected:** `SKILL.md` reported; `.vscode/settings.json` invisible (likewise `.idea/`, `.DS_Store`).
- [ ] **Note:** an **explicit** manifest gets none of these defaults — it must declare its own `collect_exclude`. Verify the sandbox's explicit manifest does NOT hide a `.vscode` file unless you add the pattern. This asymmetry is easy to forget and worth seeing once with your own eyes.

### 4.3 Old-version fails-open (optional — requires a second install)

- [ ] **Skip this section if** you don't want to downgrade/reinstall.
- [ ] **Steps:** in a separate venv, install the previous release (`git checkout <0.3.1 commit>` + `pip install -e .`), run HV.2's command against the sandbox.
- [ ] **Expected:** the unknown key is ignored; new files copy without `--add` and **no warning is printed**. This is the documented fails-open: the guard requires ≥0.4.0 everywhere the payload is collected, and nothing enforces that yet.

## What the automated tests DON'T cover

- **Real-payload glob breadth** — fnmatch's basename/segment matching against a payload with realistic name collisions (the phantom-match lesson: verification methods themselves need a known-answer control)
- **Terminal rendering** — WITHHELD/ADOPTING color and wording on Windows conhost vs Windows Terminal vs piped/NO_COLOR
- **Report masking** — the two-way REFUSING short-circuit hiding the WITHHELD list (Section 2.5)
- **Cross-version fails-open** — old ccs silently ignoring the key (Section 4.3)
- **AC-7 and AC-12** — never exercised by any test, automated or manual (Sections 2.4, 3.3)
- **Message quality** — whether the WITHHELD remediation line actually tells a confused operator what to do next

## Reporting issues found
