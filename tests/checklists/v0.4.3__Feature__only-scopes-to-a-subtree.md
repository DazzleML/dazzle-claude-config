# Human Test Checklist: `--only` Scopes to a Subtree

**Target version:** 0.4.3
**Ships with commit:** `feat: --only reaches inside an entry and matches whole path components; the two-way guard honours box tags`
**Companion automated tests:** `tests/test_only_scope.py` (18); mutation sweep `tests/mutation/v0.4.3__sweep__only-scope.md`.

## What this is

`--only` used to be a string prefix on entry paths: `--only dotclaude/skills/test-mutation` matched **no** entry (silently, with a "matched no manifest entries" warning), and `--only dotclaude/sk` matched `dotclaude/skills` by accident. Now it matches whole path components and can reach *inside* an entry: `dotclaude/skills/test-mutation` scopes `apply`, `collect`, `merge`, the two-sided guard, `--force`, and the direction skips to that subtree and nothing else. The guard also now honours box tags (a tag-gated-off entry is never refused on, since it is never copied).

What the automated tests cannot reach: your real payload's entry names, and the feel of the `--only` help text.

## Prerequisites

A scratch world with a directory entry holding three subtrees, two of which share a prefix:

**POSIX**:
```bash
W=/tmp/ccs043only; mkdir -p $W/checkout/dotclaude/skills/{a,b,ab} $W/live/skills/{a,b,ab} $W/user
printf '{"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},"entries":[{"repo":"dotclaude/skills","territory":"dotclaude","target":"skills","strategy":"copy"}]}' > $W/checkout/ccs-manifest.json
for n in a b ab; do printf "# $n v1\n" > $W/checkout/dotclaude/skills/$n/SKILL.md; printf "# $n v1\n" > $W/live/skills/$n/SKILL.md; done
git -C $W/checkout init -q -b main && git -C $W/checkout add -A && git -C $W/checkout -c user.name=t -c user.email=t@x -c commit.gpgsign=false commit -qm v1
for n in a b ab; do printf "# $n v2\n" > $W/checkout/dotclaude/skills/$n/SKILL.md; done
git -C $W/checkout -c user.name=t -c user.email=t@x -c commit.gpgsign=false commit -qam v2
CCS="ccs --checkout-dir $W/checkout --claude-dir $W/live --user-claude $W/user --no-color --no-fetch"
```

**PowerShell / cmd.exe**: the same files; write them with `python -c` or an editor, and define the `CCS` prefix as in the other 0.4.3 checklists. (`tests/checklists/helpers/` has no helper for this one -- the world is six files.)

## High-Value Verification (~3 minutes)

### HV.1 -- A subtree `--only` touches that subtree and nothing else

- [ ] **Steps:** `$CCS apply --only dotclaude/skills/a --dry-run`, then without `--dry-run`.
- [ ] **Expected:** `would apply` / `applied` lists **only** `skills/a/SKILL.md`; afterwards `live/skills/a/SKILL.md` reads `# a v2`, while `ab/` and `b/` still read `v1`. No "matched no manifest entries" warning.
- [ ] **Why this matters:** the runbook's per-skill force on a production box was a silent no-op until this.

### HV.2 -- A partial component matches nothing

- [ ] **Steps:** `$CCS apply --only dotclaude/sk --dry-run`
- [ ] **Expected:** `warning: --only 'dotclaude/sk' matched no manifest entries`; nothing listed.

### HV.3 -- The guard is scoped too

- [ ] **Steps:** make `b` two-sided: `printf '# b live edit\n' > $W/live/skills/b/SKILL.md`. Then `$CCS apply --only dotclaude/skills/a --dry-run` and `$CCS apply --only dotclaude/skills/b --dry-run`.
- [ ] **Expected:** the first proceeds (exit 0, no `REFUSING`); the second prints `REFUSING: 1 file changed on BOTH sides` naming `skills/b/SKILL.md`, exit 1.

### HV.4 -- `--force` is scoped

- [ ] **Steps:** with `b` still two-sided, also edit `a` live; `$CCS apply --only dotclaude/skills/a --force`.
- [ ] **Expected:** `a` becomes `v2`; `b` keeps `# b live edit`. Exit 0.

### HV.5 -- `merge --only` reaches a file inside a directory entry

- [ ] **Steps:** `$CCS merge --only dotclaude/skills/b --dry-run`
- [ ] **Expected:** `would merge: skills/b/SKILL.md` (and only that), followed by its base table.
