## What this is

Three issues shipped as one wave, designed against a real half-configured machine. `ccs setup box` declares a box's identity (never overwrites); `ccs doctor` verifies an environment read-only with a fix per finding; `ccs seed keep|reset|list` records the yours-or-the-payload's answer for seeded files, with `status` telling the truth about what it does not compare and auto-offering `--reseed` for unmodified stale seeds; directory `seed-if-absent` entries now seed instead of silently doing nothing. The decisive test is Section 4: a REAL machine that reached `apply` without a box declaration gets configured by these tools alone -- no runbook.

## Prerequisites

1. `ccs --version` reports the wave's version (or the editable install at its commit).
2. A scratch world, NEVER the real config. All commands below use explicit overrides, abbreviated `ccs* = ccs --checkout-dir <S>/co --claude-dir <S>/live --user-claude <S>/user --no-color --no-fetch`:

   **POSIX** (translate paths for cmd/PowerShell as in previous checklists):
   ```bash
   S=/tmp/ccs-052-check && mkdir -p "$S" && cd "$S"
   git init -q -b main co && cd co && mkdir dotclaude
   printf '%s' '{"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"}},"entries":[{"repo":"dotclaude/CLAUDE.md","territory":"dotclaude","target":"CLAUDE.md","strategy":"seed-if-absent"}]}' > ccs-manifest.json
   printf 'old seed v1\nline\n' > dotclaude/CLAUDE.md
   git add -A && git commit -qm v1
   printf 'new stub v2\n' > dotclaude/CLAUDE.md && git commit -qam v2
   cd .. && mkdir live user
   ```
3. Reset between sections: delete `<S>/user/ccs-seed-decisions.json` and `<S>/user/ccs-box.json`; empty `<S>/live`.

## High-Value Verification (~5 minutes)

### HV.1 -- doctor tells a broken world the truth, and fixes nothing
- [ ] **Steps:** `ccs --checkout-dir <S>/nowhere --user-claude <S>/user --no-color doctor`
- [ ] **Expected:** `[FAIL] checkout not found ...` naming the fix; verdict "not usable yet"; exit 2; NOTHING created on disk.
- [ ] **Why this matters:** doctor's whole contract is read-only honesty; a doctor that writes or flatters is worse than none.

### HV.2 -- setup box declares once and refuses twice
- [ ] **Steps:** `ccs* setup box --name scratchbox --tag testing` then repeat with `--name other`.
- [ ] **Expected:** first: `declared: box scratchbox, tags scratchbox, testing`; second: "never overwrites", file unchanged. `type`/`cat` the JSON: name first, name included in tags.
- [ ] **Why this matters:** identity is a deliberate statement; a re-run that silently rewrote it would corrupt the tags gate fleet-wide.

### HV.3 -- the untouched-stale seed is offered, not questioned
- [ ] **Steps:** put seed v1 in live WITH CRLF endings (`printf 'old seed v1\r\nline\r\n' > <S>/live/CLAUDE.md`), then `ccs* status`.
- [ ] **Expected:** `seeded ... an older seed, unmodified -- ... ccs apply --reseed CLAUDE.md`; NO "yours or the payload's?"; exit 0.
- [ ] **Why this matters:** this is the real-machine migration case, CRLF included -- the measured landmine where a raw comparison never fires.

### HV.4 -- the question is asked once and the answer sticks
- [ ] **Steps:** `printf 'my own\n' > <S>/live/CLAUDE.md`; `ccs* status` (expect the question); `ccs* seed keep CLAUDE.md`; `ccs* status` (quiet); commit a v3 seed in co; `ccs* status`.
- [ ] **Expected:** question -> quiet -> "the seed changed since you chose to keep yours".
- [ ] **Why this matters:** the anti-nag contract: one question, hash-anchored re-ask, never a daily drumbeat.

### HV.5 -- a directory seed delivers, and never overwrites
- [ ] **Steps:** add a directory entry (see `tests/test_dir_seed.py`'s manifest) with two files; pre-create one of them in live with your own content; `ccs* apply`.
- [ ] **Expected:** the absent file seeded (one line each), your pre-existing file byte-identical after.
- [ ] **Why this matters:** #28's silent no-op replaced by delivery, with the never-overwrite rule intact -- the exact pair of properties that make seeds trustworthy.

### HV.6 -- the clean verdict stops overclaiming
- [ ] **Steps:** with the customized live CLAUDE.md from HV.4 still in place and kept: `ccs* status`.
- [ ] **Expected:** `status: clean -- everything ccs syncs matches ... (1 seeded file is yours and not compared)`; exit 0.
- [ ] **Why this matters:** the sentence that started #27 -- "your live config and the checkout match" was measured false by a thousand lines on a real box.

## Section 1: doctor details (~5 min)
- [ ] 1.1 Healthy world (box declared, remote added): all `[ OK ]`, "fully configured", exit 0.
- [ ] 1.2 Missing box file only: `[WARN] no box file ... ccs setup box creates it`, exit 1.
- [ ] 1.3 Malformed `ccs-config.json`: WARN names the file, defaults in effect.
- [ ] 1.4 Open seed question present: doctor repeats it as a WARN (the #27 integration).
- [ ] 1.5 A payload with `scripts/probe_layers.py`: `[info]` line points at it.
- [ ] 1.6 TTY colors: OK green, WARN yellow, FAIL red; plain when piped.

## Section 2: seed decisions details (~5 min)
- [ ] 2.1 `ccs seed keep CLAUDE.md --always` -> status quiet forever, `--long` shows "yours (kept, always)".
- [ ] 2.2 `ccs seed reset CLAUDE.md` -> question returns.
- [ ] 2.3 `ccs seed keep F.md` (a copy entry) -> exit 2, "not a seed entry".
- [ ] 2.4 Hand-edit `ccs-seed-decisions.json` to garbage -> status warns, treats as no decisions (asks again; never widens).
- [ ] 2.5 `ccs seed list` -> every state labeled, readable.

## Section 3: directory seeds details (~4 min)
- [ ] 3.1 Deny pattern inside the directory: file refused loudly, siblings seeded.
- [ ] 3.2 `--only <entry>/<subdir>`: seeds only inside; out-of-scope subtree untouched.
- [ ] 3.3 `--reseed <entry>/<file>`: that one file re-taken, backup dir reported.
- [ ] 3.4 `--dry-run`: reports, writes nothing.

## Section 4: MANUAL -- the real acceptance run (operator only)

> The wave was designed against a real half-configured machine (no box file,
> stale monolithic seed). These steps configure it with the NEW TOOLS ONLY --
> no runbook, no manual file moves. Every place the tools fall short of
> carrying you is a finding.

- [ ] 4.1 `ccs doctor` on the half-configured box: expect WARN no-box-file (+ its fix line), WARN seeded CLAUDE.md untouched-old (+ `--reseed` offer), remote OK, verdict "usable, with things worth fixing", exit 1.
- [ ] 4.2 `ccs setup box --name <box> ` -- declaration created; `ccs status --long` shows the `not for` gate block.
- [ ] 4.3 Independent backup by hand (the ONE remaining manual step -- migration recipes are the epic's slice 4): copy the live CLAUDE.md aside.
- [ ] 4.4 `ccs apply --reseed CLAUDE.md` exactly as status/doctor suggested; byte-compare the tool's backup against your copy.
- [ ] 4.5 `ccs doctor` again: expect "fully configured", exit 0.
- [ ] 4.6 Payload verifier (probe) + a fresh Claude session, your eyes.
- [ ] 4.7 Write down every moment a private doc was still needed -- each is a finding for the epic's next slice.
