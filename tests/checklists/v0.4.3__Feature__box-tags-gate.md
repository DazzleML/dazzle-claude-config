# Human Test Checklist: The Box Tags Gate

**Target version:** 0.4.3 (first slice; the version bumps when the release's remaining pieces land)
**Ships with commit:** `feat: manifest entries can require box tags; a box declares its tags in ~/claude/ccs-box.json`
**Companion automated tests:** 218 total; 28 in `tests/test_tags_gate.py` + 5 in `tests/test_tags_gate_tester.py` (directory and seed entries under the gate). Mutation-checked (`tests/mutation/v0.4.3__sweep__box-tags-gate.md`): 12 fresh-context mutants, 7 killed on the first pass, the 5 survivors all killable and killed by tests added on the spot; with the predicate made to ignore tags, 10 tests fail.

## What this is

Until now a manifest entry could be limited by operating system (`"os": "windows"` / `"posix"`) and by nothing else. Files that belong to one machine -- its own operating manual, a hook only that box runs -- had no way to say so; `machines/<NAME>/` was a directory convention the tool never read. Now an entry may carry `"tags": ["..."]`, and a box declares what it is in `~/claude/ccs-box.json`:

```json
{"name": "prod-vps", "tags": ["prod-vps", "production"]}
```

An entry applies on a box only when **every** tag it names is declared there -- and the same rule gates `collect`, so a box without the tag can never stage that file into the shared checkout. A missing or broken box file means "no tags", which switches tag-gated entries **off**, never on. `status --long` lists what the gate kept off this box and why. `os` values are now validated (`linux` used to parse and then silently never apply anywhere).

What the automated tests cannot reach: your real manifest and real box file, the look of the `not for` block in a colour terminal, a second machine actually declining a file the first one carries, and whether the words on screen make sense to someone who did not write them.

## Prerequisites

1. `ccs --version` shows a 0.4.3 build (or a checkout at/after the commit above with `pip install -e .`).
2. A scratch world -- nothing below touches `~/.claude` or `~/claude`. Pick a directory that does not exist yet.

   **cmd.exe**:
   ```cmd
   set W=%TEMP%\ccs043
   mkdir %W%\checkout\dotclaude %W%\checkout\machines\prod-vps %W%\live %W%\user
   python -c "import json,pathlib,os;w=os.environ['W'];pathlib.Path(w+r'\checkout\ccs-manifest.json').write_text(json.dumps({'manifest_version':1,'territories':{'dotclaude':{'root_var':'CLAUDE_DIR','repo_dir':'dotclaude'},'userclaude':{'root_var':'USER_CLAUDE','repo_dir':'userclaude'}},'entries':[{'repo':'dotclaude/F.md','territory':'dotclaude','target':'F.md','strategy':'copy'},{'repo':'machines/prod-vps/machine.md','territory':'userclaude','target':'claude-config/machine.md','strategy':'copy','tags':['prod-vps']}]}));pathlib.Path(w+r'\checkout\dotclaude\F.md').write_text('shared\n');pathlib.Path(w+r'\checkout\machines\prod-vps\machine.md').write_text('# the box manual\n');pathlib.Path(w+r'\live\F.md').write_text('shared\n')"
   git -C %W%\checkout init -q -b main && git -C %W%\checkout add -A && git -C %W%\checkout -c user.name=t -c user.email=t@x -c commit.gpgsign=false commit -qm seed
   set CCS=ccs --checkout-dir %W%\checkout --claude-dir %W%\live --user-claude %W%\user --no-color --no-fetch
   ```

   **PowerShell**: same commands with `$env:W` for `%W%`, and `function ccs043 { ccs --checkout-dir $env:W\checkout --claude-dir $env:W\live --user-claude $env:W\user --no-color --no-fetch @args }`.

   **POSIX**:
   ```bash
   W=/tmp/ccs043
   mkdir -p $W/checkout/dotclaude $W/checkout/machines/prod-vps $W/live $W/user
   printf '{"manifest_version":1,"territories":{"dotclaude":{"root_var":"CLAUDE_DIR","repo_dir":"dotclaude"},"userclaude":{"root_var":"USER_CLAUDE","repo_dir":"userclaude"}},"entries":[{"repo":"dotclaude/F.md","territory":"dotclaude","target":"F.md","strategy":"copy"},{"repo":"machines/prod-vps/machine.md","territory":"userclaude","target":"claude-config/machine.md","strategy":"copy","tags":["prod-vps"]}]}' > $W/checkout/ccs-manifest.json
   printf 'shared\n' > $W/checkout/dotclaude/F.md; printf '# the box manual\n' > $W/checkout/machines/prod-vps/machine.md; printf 'shared\n' > $W/live/F.md
   git -C $W/checkout init -q -b main && git -C $W/checkout add -A && git -C $W/checkout -c user.name=t -c user.email=t@x -c commit.gpgsign=false commit -qm seed
   CCS="ccs --checkout-dir $W/checkout --claude-dir $W/live --user-claude $W/user --no-color --no-fetch"
   ```

   Below, `$CCS` stands for your shell's form. **Reset**: delete `$W/user/ccs-box.json` and `$W/user/claude-config` (or the whole scratch directory; `dz safedel` if you have it) and rebuild.

## High-Value Verification (~3 minutes)

### HV.1 -- No box file: the tagged entry is simply not there

- [ ] **Steps:** `$CCS status --long`, then `$CCS apply`.
- [ ] **Expected:** `compared 1 file across 1 entry`; a block
  ```
  not for   this box (tags declared: none)
            machines/prod-vps/machine.md -- needs tags: prod-vps
  ```
  `apply` copies nothing; `$W/user/claude-config/machine.md` does not exist. Exit 0 both times.
- [ ] **Why this matters:** the safe direction. A fresh machine with no declaration must never receive another box's files.

### HV.2 -- Declare the tag: the entry applies

- [ ] **Steps:** write `$W/user/ccs-box.json` containing `{"name": "prod-vps", "tags": ["prod-vps"]}`. `$CCS status --long`, then `$CCS apply`, then `$CCS status`.
- [ ] **Expected:** `compared 2 files across 2 entries`; no `not for` block; `apply` prints `applied: claude-config/machine.md` (the live path); the file exists under `$W/user/claude-config/`; final `status: clean`.

### HV.3 -- The important half: an untagged box cannot spread the file

- [ ] **Steps:** keep `$W/user/claude-config/machine.md` from HV.2 but delete `$W/user/ccs-box.json`. Edit the live file (append a line). `$CCS collect --dry-run`, then `$CCS collect`.
- [ ] **Expected:** neither run mentions `machine.md`; `git -C $W/checkout status --porcelain` is empty afterwards. The checkout copy still reads `# the box manual`.
- [ ] **Why this matters:** without this, one box's manual would ride `collect` into the shared payload and land on every other machine at the next `apply`.

### HV.4 -- A broken box file narrows, never widens

- [ ] **Steps:** write `$W/user/ccs-box.json` containing `{not json`. `$CCS status --long`.
- [ ] **Expected:** first line `warning: box config: ...ccs-box.json: JSONDecodeError: ...`; then the same `not for` block as HV.1 (`tags declared: none`). Exit 0.

### HV.5 -- A typo in `os` is refused, not ignored

- [ ] **Steps:** edit `$W/checkout/ccs-manifest.json`: on the `dotclaude/F.md` entry add `"os": "linux"`. `$CCS status`.
- [ ] **Expected:** `ccs: entry 0: invalid os 'linux' (valid: ['posix', 'windows'])`, exit 2. Restore the manifest (remove the key).

## Section 1: Tag rules

### 1.1 Every tag, not any tag

- [ ] **Steps:** change the manifest entry to `"tags": ["prod-vps", "production"]` (commit it). Box file: `{"name": "prod-vps", "tags": ["prod-vps"]}`. `$CCS status --long`.
- [ ] **Expected:** `not for box prod-vps (tags declared: prod-vps)` / `... -- needs tags: production`. Add `production` to the box file: the block disappears and the entry counts.

### 1.2 Tag grammar

- [ ] **Steps:** box file `{"name": "x", "tags": ["ok", "Not OK", "a b"]}`; `$CCS status --long`.
- [ ] **Expected:** two `warning: box config: ... bad tag ...` lines; `tags declared: ok`. Manifest side: put `"tags": ["Badtag"]` on an entry -- `ccs: entry N: bad tag 'Badtag' (...)`, exit 2.

### 1.3 `CCS_BOX_TAGS` for a one-off run

- [ ] **Steps:** with no box file, set `CCS_BOX_TAGS=prod-vps` (cmd: `set CCS_BOX_TAGS=prod-vps`; PowerShell: `$env:CCS_BOX_TAGS = "prod-vps"`; POSIX: `export CCS_BOX_TAGS=prod-vps`) and run `$CCS status --long`.
- [ ] **Expected:** the entry applies (2 entries, no `not for`). Unset it; back to HV.1. With a box file present, the env var **replaces** its tags for that run.

### 1.4 `os` and `tags` combine

- [ ] **Steps:** entry with `"os": "posix", "tags": ["prod-vps"]`; box declares the tag. `$CCS status --long` on Windows, and on a POSIX box if you have one.
- [ ] **Expected:** Windows: `-- needs os: posix` (the os reason wins; tags are not mentioned). POSIX with the tag: applies.

## Section 2: Against your real payload (read-only)

- [ ] `ccs status --long` on a machine with no `~/claude/ccs-box.json` -- output identical to before the upgrade, plus (only if your manifest already has `os` entries for the other platform) a `not for` block naming them. Exit code unchanged.
- [ ] Create `~/claude/ccs-box.json` with your machine's name and one tag; `ccs status` -- still clean, nothing changed (no real entry carries tags yet).
- [ ] Read the `not for` block aloud to someone who has not seen the manifest: do they understand why those files are not on this machine?

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|

## What the automated tests DON'T cover

- Your real manifest and a real second machine declining a file
- Colour of the `not for` block; wording clarity
- A POSIX box combining `os` and `tags` (1.4)
- `~` expansion when `--user-claude` is not given (the default path)

## Reporting issues found

Note the section, the exact command, the contents of `ccs-box.json` and the entry's `tags`/`os`, and the `not for` block as printed.

## Cleanup

Delete the scratch directory. If you created `~/claude/ccs-box.json` in Section 2, keep it -- it is the box's declaration from here on -- or delete it to return to "no tags".
