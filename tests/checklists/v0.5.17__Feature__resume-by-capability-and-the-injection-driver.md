# Human Test Checklist: resume by tool capability, and the injection driver

**Target version:** v0.5.17
**Ships with commit:** feat: resume a merge in the tool only when it keeps the work (v0.5.17)
**Companion automated tests:** 49 tests -- `tests/test_tool_capability.py` (22), `tests/test_inject_driver.py` (15, two written to kill mutation survivors), `tests/test_inject_flow.py` (12); the resume tests in `tests/test_adoption_merge.py` still stand. Mutation sweep: 12 of 13 killed, the survivor equivalent (`tests/mutation/v0.5.17__sweep__resume-by-capability-and-injection.md`).

## What this is

Since v0.5.15 a file you already resolved is never reopened, because the common merge tools regenerate their output pane and would discard your work. v0.5.16 gave ccs the knowledge of which tools do that; v0.5.17 acts on it. A tool that shows what is on disk (vimdiff) reopens resumed files freely. For BeyondCompare on Windows, `ccs merge --relaunch` reopens the tool and **paints your prior work back into its output pane** -- after warning you, with the keyboard taken for about a second, verified by reading the saved file back, and restored from a snapshot if anything goes wrong. `--relaunch --discard` is the old destructive reopen, named.

The automated tests stand in for the GUI with spies. What only a person can verify is the part that touches a real window: that the paint lands in the right pane, that focus and clipboard come back, that the warning reads right, and that the real workspace behaves. This document is that verification. **Every step that opens a diff tool is inherently MANUAL** -- an agent must not fake it.

## Prerequisites

1. **Platform.** Sections 2, 3, 4 and HV.1-HV.4 need **Windows** with BeyondCompare 4 or 5 configured as your git merge tool (`git config merge.tool` prints `bc`; `mergetool.bc.cmd` and `mergetool.bc.path` set). Section 1 and HV.5 run on any platform; HV.5 needs `vim`.
2. **Isolation -- all three overrides, on every command.** `ccs --help` shows `--checkout-dir` honours `CCS_CHECKOUT_DIR` and `--claude-dir` honours `CLAUDE_CONFIG_DIR`; **`--user-claude` has no environment variable and must be passed as a flag each time.** A run that reaches your real `~/.claude` or `~/claude` is a defect in this checklist, not a test.

   **cmd.exe**:
   ```cmd
   set CCS_CHECKOUT_DIR=%TEMP%\ccs-chk\checkout
   set CLAUDE_CONFIG_DIR=%TEMP%\ccs-chk\live
   set U=--user-claude %TEMP%\ccs-chk\user
   ```
   **PowerShell**:
   ```powershell
   $env:CCS_CHECKOUT_DIR = "$env:TEMP\ccs-chk\checkout"
   $env:CLAUDE_CONFIG_DIR = "$env:TEMP\ccs-chk\live"
   $U = "--user-claude", "$env:TEMP\ccs-chk\user"
   ```
   **POSIX**:
   ```bash
   export CCS_CHECKOUT_DIR=/tmp/ccs-chk/checkout
   export CLAUDE_CONFIG_DIR=/tmp/ccs-chk/live
   U="--user-claude /tmp/ccs-chk/user"
   ```
   Every `ccs` command below is written as `ccs %U% ...` (cmd), `ccs $U ...` (PowerShell), `ccs $U ...` (POSIX).
3. **Scratch world.** One two-sided file with an ancestor, the shape of `tests/test_adoption_merge.py::world`:

   ```
   <checkout>/ccs-manifest.json   one entry: dotclaude/CLAUDE.md -> CLAUDE.md, strategy copy
   <checkout>/dotclaude/CLAUDE.md  "theirs", committed twice so a base exists
   <live>/CLAUDE.md                "ours", differing from theirs in one paragraph
   <user>/                         empty
   ```
   **Scratch-git rules:** every git command carries `-C <checkout>` so it can never land in a real repo, and every commit carries `-c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false`. Never change global git config for a checklist run.

   ```
   git -C <checkout> init -q -b main
   git -C <checkout> -c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false add -A
   git -C <checkout> -c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false commit -qm "base"
   (edit dotclaude/CLAUDE.md -- change one paragraph)
   git -C <checkout> -c user.email=t@t -c user.name=t -c commit.gpgsign=false -c tag.gpgsign=false commit -qam "theirs"
   ```
   Then write `<live>/CLAUDE.md` as the base text with a *different* change to the same paragraph.
4. **Reset between sections:** delete the workspace `<user>/merge/ccs/` (`rmdir /s /q` / `Remove-Item -Recurse` / `rm -rf`). Nothing else accumulates.

## High-Value Verification (~5 minutes, Windows + BC unless marked)

**If you only have 5 minutes**, run these five. They cover the highest-impact user-visible behavior this commit introduces. If any fails, the work is broken.

### HV.1 -- a resumed file is painted back in (MANUAL)

Validates: the whole driver on a real window -- locate, gate, paint, save, read back.

- [ ] **Steps:**
  1. `ccs $U merge` -- BC opens. Resolve the conflict by hand, save, close BC.
  2. `ccs $U merge` again -- expect `resumed CLAUDE.md -- differs from the generated seed; keeping it as yours` and **no** BC window.
  3. `ccs $U merge --relaunch` -- read the warning, answer `y` at `paint your prior work into the tool now? [y/N]`.
- [ ] **Expected:** BC opens; its output pane shows a regenerated merge for a moment and then **your resolution**; ccs prints `reopened CLAUDE.md -- your prior edits were painted back into bc and verified`. Close BC.
- [ ] **Why this matters:** this is the feature. If the pane keeps the regenerated merge, the paint failed and the run must say so (HV.3, Section 3).

### HV.2 -- declining launches nothing (MANUAL)

- [ ] **Steps:** same state; `ccs $U merge --relaunch`, answer `n`.
- [ ] **Expected:** `not reopened CLAUDE.md -- declined at the prompt ...`; BC never opens; `<user>/merge/ccs/CLAUDE.md.merged` is byte-identical to before (`fc /b` / `Compare-Object (Get-Content ...)` / `cmp`).
- [ ] **Why this matters:** a declined consent that still launched would be the destructive reopen wearing a prompt.

### HV.3 -- an already-open session is refused before launch (MANUAL)

- [ ] **Steps:** leave BC open on the file from HV.1. `ccs $U merge --relaunch`, answer `y`.
- [ ] **Expected:** `not reopened CLAUDE.md -- bc already has CLAUDE.md.merged open -- close that tab first ...`; **no second tab** appears in BC.
- [ ] **Why this matters:** measured in p1 -- a relaunch of an open file creates a hidden second session whose close-time save prompt would overwrite the work. Refusing beforehand is the only clean fix.

### HV.4 -- focus and clipboard come back (MANUAL)

- [ ] **Steps:** put a distinctive string on the clipboard; focus a different window; run HV.1 step 3 again. Then repeat once with an **empty** clipboard.
- [ ] **Expected:** after the paint, the clipboard holds your string (paste it to see); the window that had focus has it again. With the empty clipboard beforehand it is **empty** afterwards -- not a single space.
- [ ] **Why this matters:** a driver that leaves your merge on the clipboard, or focus in BC, changed state you did not ask to change.

### HV.5 -- vimdiff reopens resumed files by itself (MANUAL; any platform)

- [ ] **Steps:** `ccs $U merge --tool vimdiff` -- resolve, `:wqa`. Edit `<user>/merge/ccs/CLAUDE.md.merged` by hand (add a line). `ccs $U merge --tool vimdiff` again, **no flags**.
- [ ] **Expected:** vim opens with your edited file in the MERGED window and ccs prints `reopened CLAUDE.md -- vimdiff shows what is on disk, so your edits are in the tool`.
- [ ] **Why this matters:** the capability model's other half -- a tool that preloads needs no flag and no driver.

## Section 1: the capability registry (any platform, ~5 min)

### 1.1 doctor names the registry and the driver

- [ ] **Steps** (same across all shells): `ccs $U doctor --no-fetch`
- [ ] **Expected:** `[ OK ] merge tools: 5 named, 6 by executable, 1 injection profile(s)`. On Windows: `[ OK ] injection driver ready (PowerShell + inject.ps1) ...`. On POSIX: an `info` line that the driver is not applicable here and resumed files stay closed for regenerating tools.

### 1.2 a user overlay wins, and a broken one is reported

- [ ] **Steps:**
  1. Write `<user>/merge-tools.json` containing `{"tools": {"bc": {"resume": "writes-only"}}}` (any shell: `python -c "open(r'<user>/merge-tools.json','w').write('{\"tools\": {\"bc\": {\"resume\": \"writes-only\"}}}')"`).
  2. With a resumed file: `ccs $U merge --relaunch` (MANUAL).
  3. Overwrite the file with `{not json`; `ccs $U doctor --no-fetch`.
- [ ] **Expected:** step 2 reopens BC the OLD way -- no warning, no paint (the overlay demoted `bc`). Step 3: a `WARN` line naming the file, and the packaged table stands (`merge tools: ...` still `[ OK ]`).
- [ ] **Check:** delete the overlay afterwards (`del` / `Remove-Item` / `rm -f`).

### 1.3 `merge_inject: never`

- [ ] **Steps:** `ccs $U setup update` (adds the key at `ask`); edit `<user>/ccs-config.json` to `"merge_inject": "never"`; with a resumed file, `ccs $U merge --relaunch`.
- [ ] **Expected:** `not reopened CLAUDE.md -- merge_inject is 'never' -- set it to 'ask' or 'always' ...`; nothing launched.
- [ ] **Check:** `ccs $U setup update --explain merge_inject` prints the explanation offline, naming `ask`, `always`, `never`. Set the key back to `ask`.

## Section 2: `--discard` (Windows + BC, MANUAL, ~2 min)

### 2.1 the destructive reopen is explicit and named

- [ ] **Steps:** with a resumed file, `ccs $U merge --relaunch --discard`.
- [ ] **Expected:** no warning, no prompt; BC opens on a regenerated merge; ccs prints `reopened WITHOUT your edits CLAUDE.md -- --discard: the tool regenerated its output`.
- [ ] **Check:** save in BC and close; the next `ccs $U merge` reports the file resumed with the *regenerated* content -- that is the behavior you asked for by name.

## Section 3: failure halfway (Windows + BC, MANUAL, ~5 min)

### 3.1 the restore

- [ ] **Steps:**
  1. Make the paint fail on purpose: write `<user>/merge-tools.json` with a wrong landmark:
     `{"inject_profiles": {"bc5": {"os": "windows", "window": {"class": "TViewForm", "title_suffix": " - Text Merge - Beyond Compare"}, "pane": {"class": "TTextEditor", "landmark": {"class": "TUiRadioButton", "text": "NoSuchButton"}}}}}`
  2. `ccs $U merge --relaunch`, answer `y`. BC opens on the regenerated merge. **Save and close it.**
- [ ] **Expected:** `injection failed CLAUDE.md -- the tool's output pane could not be located after launch ... close it WITHOUT saving`, then -- because you saved anyway -- `restored CLAUDE.md -- the tool saved over your unverified edits; ccs put them back`.
- [ ] **Check:** `<user>/merge/ccs/CLAUDE.md.merged` holds **your** resolution, not the regenerated one; no `CLAUDE.md.merged.pre-inject` or `.before.json` remains. Delete the overlay.

### 3.2 Ctrl+C while BC is open

- [ ] **Steps:** HV.1 step 3; while BC is open (after the paint), press Ctrl+C in the terminal.
- [ ] **Expected:** ccs exits with the `cancelled -- your diff tool is still open` message; BC stays open; the `.merged` file is unchanged; no sidecars remain in the workspace.

## Section 4: exit codes (Windows + BC, MANUAL, ~2 min)

- [ ] **Steps:** reset the workspace; `ccs $U merge`; close BC **without** resolving or saving (answer `No` to its save prompt).
- [ ] **Expected:** a dim line `bc exited 101 for CLAUDE.md -- the output was not saved`.
- [ ] **Check:** resolve and save on a second run: no exit line (0 is silent).

## Section 5: the run that matters -- the maintainer's real workspace (MANUAL, maintainers only)

*External testers skip this section; it needs the maintainer's own merge workspace.*

- [ ] With the real multi-file workspace in place and its durable backups confirmed, run `ccs merge --only <one entry> --relaunch` on one already-resolved file. Expected: HV.1's behavior on real content. Capture the output pane before and after with the screenshot tooling; keep the captures project-private.
- [ ] Then `ccs merge --accept --no-launch` to install the resolved set. One file is expected to be refused for a duplicated line until it is fixed by hand; the run must name it.

## What the automated tests DON'T cover

- That the paint lands in the **right** pane of a real BeyondCompare window -- the spies return canned handles.
- Focus and clipboard restoration on a real desktop; whether the ~1 s takeover is tolerable in practice.
- The warning's wording as read by someone who did not write it.
- BC's actual exit codes through *your* `mergetool.bc.path`: p1 measured `BComp.exe`; a `BCompare.exe` path may return before the window closes.
- PowerShell Constrained Language Mode on a locked-down box: the driver refuses with exit 3 and doctor says why -- untested here.
- Codepage rendering of the new messages on cmd.exe (437/1252).
- Two BeyondCompare versions configured under different names on one box (an open follow-up: the executable rule treats them alike).

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and output; for anything visual, capture the pane (the child control), not the whole screen.
3. Keep the workspace files (`<user>/merge/ccs/*.merged`, `.seed`, any `.pre-inject`) -- they are the evidence.
4. File an issue referencing this checklist and #49, and the version.
